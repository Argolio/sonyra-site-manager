# SONYRA Manager Sections

Этот документ фиксирует ответственность семи постоянных разделов protected `/manager` в SONYRA Site Manager.

Section-module boundary standard зафиксирован в `/Users/stanislavkataev/projects/SONYRA Site Platform/SONYRA Site Manager/docs/SONYRA_SECTION_MODULE_STANDARD.md`.

## Постоянные разделы

Семь базовых разделов остаются постоянными:

- Главное;
- Сайт;
- Страницы;
- Дизайн;
- Модули;
- Безопасность;
- Настройки.

Расширения добавляют свои блоки внутрь этих разделов, а не ломают меню, sidebar или page header.

Начиная с версии `0.1.67`, единый Manager Notice Center относится к manager shell, располагается под page header и используется всеми разделами для важных ошибок, предупреждений, системных сообщений, license/update notices и будущих extension promos.

Начиная с версии `0.1.68`, раздел “Сайт” на route `setup` имеет первый реальный foundation screen вместо placeholder. Экран показывает публичную основу сайта без сохранения, публикации, DB writes, REST save endpoint и public rendering.

## A. Главное

Раздел “Главное” отвечает за:

- dashboard;
- setup mode;
- working mode;
- dashboard cards от базы;
- dashboard cards от расширений;
- setup steps от базы;
- setup steps от расширений;
- важные уведомления;
- состояние базовых элементов;
- состояние документов;
- состояние cookie;
- состояние форм;
- состояние безопасности;
- состояние модулей;
- базовые показатели сайта;
- предупреждения по лицензии, связи и обновлениям;
- popup/modal после завершения настройки сайта.

Начиная с версии `0.1.66`, “Главное” имеет первый dashboard foundation:

- setup dashboard для первичной подготовки сайта;
- working dashboard foundation без fake analytics;
- core setup steps для сайта без расширений;
- extension slots для будущих cards, steps, warnings и metrics;
- hidden completion modal foundation без автоматического показа.

Обязательная логика:

- первая задача “Главного” — настройка сайта;
- настройка есть всегда, даже если расширения не подключены;
- если подключено расширение, оно добавляет свои шаги настройки;
- после завершения настройки сайт переходит в working dashboard;
- без расширений working dashboard показывает базовые данные сайта: посещения, просмотры, переходы между страницами, формы, ошибки, SEO/поведенческие показатели, документы, cookie и безопасность;
- с расширениями working dashboard дополняется их метриками.

В `0.1.66` реальные метрики не показываются. Любые показатели появляются только после настройки, проверок и подключения источников данных.

В `0.1.67` общие warnings и ошибки “Главного” должны проходить через Notice Center над dashboard content, чтобы promo и системные ошибки не конкурировали хаотично внутри карточек.

- оферта;

- согласие на рассылку;
- политика cookie;
- cookie-баннер;
- версии документов;
- активная версия документа;
- архивные версии;

В `0.1.68` реализован только foundation UI:

- контрольный список готовности к публикации.

Route “Сайт” остаётся `setup`; новый route и новый plugin slug не создаются.

## F. Безопасность

Раздел “Безопасность” отвечает за:

- владельцев и администраторов конкретного сайта;
- роли;
- права;
- вход в управление сайтом;
- email OTP;
- быстрый 4-значный код;
- доверенные устройства;
- активные сеансы;
- журнал входов;
- журнал действий;
- пользователей личного кабинета, если модуль включён;
- вход пользователей в личный кабинет;
- активные сеансы пользователей;
- журнал согласий;
- cookie-согласия;
- согласия в формах;
- согласия в онлайн-записи;
- согласия в личном кабинете;
- согласия при оплате;
- версию документа;
- дату и время согласия;
- страницу, форму или модуль, где дано согласие;
- IP/user agent, если хранится по security/legal contract;
- экспорт журнала;
- фильтры журнала;
- предупреждения безопасности.

Тексты документов и cookie-настройки находятся в “Сайт”. Факты согласий и журнал согласий находятся в “Безопасность”.

## Extension Placement Rule

Расширение должно добавлять функциональность в подходящий базовый раздел:

- витрина, установка, состояние и настройки модуля — в “Модули”;
- блоки и секции страницы — в “Страницы”;
- visual presets и tokens — в “Дизайн”;
- документы и cookie requirements — в “Сайт”;
- consent facts, audit events и security warnings — в “Безопасность”;
- service settings и diagnostics — в “Настройки”;
- dashboard cards, setup steps и metrics — в “Главное”.

Новые основные пункты меню запрещены без отдельного архитектурного решения.
