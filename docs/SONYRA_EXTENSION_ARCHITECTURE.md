# SONYRA Extension Architecture

Этот документ фиксирует архитектурный контракт SONYRA Site Manager как базового управляющего плагина и foundation для будущих расширений SONYRA Site Platform.

## Канонические роли

- Платформа: SONYRA Site Platform.
- Базовый плагин: SONYRA Site Manager.
- Видимое русское название базового плагина: ПУЛЬТ САЙТА.
- Издатель: SONYRA STUDIO.
- Правообладатель, лицензиар и продавец: ИП Катаев С.А.
- Краткая техническая форма правообладателя: IPKTFSA.

Неканонические варианты названия запрещены. Во всех документах, коде и UI используется только SONYRA.

## Base Plugin Contract

SONYRA Site Manager — базовый управляющий WordPress-плагин.

Он устанавливается физически на каждый WordPress-сайт и может работать самостоятельно без дополнительных расширений. В базовом режиме плагин поддерживает простой сайт-визитку или лендинг.

В базовом режиме допустимы:

- шапка сайта;
- подвал сайта;
- страницы;
- секции;
- базовые блоки;
- формы;
- дизайн;
- юридические документы;
- cookie;
- согласия;
- базовая безопасность;
- базовые уведомления;
- базовые настройки;
- базовый dashboard.

Core не должен превращаться в магазин, клинику, НКО, корпоративный сайт, блогера, артиста или CRM. Типовые сайты реализуются отдельными расширениями.

## Future Extension Line

Примеры будущей линейки расширений:

- SONYRA Shop;
- SONYRA Booking;
- SONYRA Corporate;
- SONYRA NGO;
- SONYRA Blog;
- SONYRA Artist;
- SONYRA Clinic.

Эти названия являются архитектурными примерами. В текущем патче не создаются плагины этой линейки, не добавляется их код в core и не добавляются их пункты меню.

## Extension Plugin Contract

Расширение — это отдельный WordPress-плагин.

Расширение физически устанавливается на тот же WordPress-сайт, где установлен SONYRA Site Manager. Код расширения не исполняется удалённо по API. Удалённый API может отдавать catalog, license status, manifest, update metadata, package URL, checksum, signature и cloud-service endpoints, но не заменяет локальную установку кода.

Установка и обновление расширений в будущей реализации должны идти через штатную механику WordPress installer/upgrader и только после проверки пакета.

## Что могут регистрировать расширения

Расширения могут регистрировать:

- dashboard cards в “Главное”;
- setup steps в “Главное”;
- working metrics в “Главное”;
- модули в “Модули”;
- настройки в “Настройки”;
- типы страниц в “Страницы”;
- секции в “Страницы”;
- блоки в “Страницы”;
- visual presets в “Дизайн”;
- документы в “Сайт”;
- cookie и specific consent requirements в “Сайт”;
- события в “Безопасность”;
- записи в журнал действий;
- записи в журнал согласий;
- health checks;
- notifications.

## Что запрещено расширениям

Расширения не могут:

- ломать семь базовых разделов;
- добавлять основные пункты меню без отдельного архитектурного решения;
- подменять sidebar;
- подменять базовую дизайн-систему;
- приносить хаотичный UI;
- обходить i18n;
- обходить security rules;
- хранить секреты в браузере;
- менять core DB напрямую без контракта;
- обходить журнал согласий, если расширение собирает согласия;
- обходить юридические документы, если расширение собирает персональные данные;
- добавлять hardcoded SVG;
- добавлять английские UI-строки.

## Seven Sections Integration Rule

Семь базовых разделов являются постоянными:

- Главное;
- Сайт;
- Страницы;
- Дизайн;
- Модули;
- Безопасность;
- Настройки.

Расширения добавляют свои блоки, карточки, настройки, проверки и события внутрь этих разделов. Они не ломают главное меню и не заменяют базовый manager shell.

## Repository And Marketplace Contract

`updates.dobromap.ru` — технический приватный репозиторий, сервер обновлений, лицензий и пакетов. Это не обязательная публичная витрина первого этапа.

Витрина расширений должна находиться внутри SONYRA Site Manager в разделе “Модули”. Сервер обновлений может отдавать:

- catalog;
- manifest;
- version;
- changelog;
- license status;
- package URL;
- checksum;
- signature;
- compatibility;
- dependencies;
- minimum SONYRA Site Manager version;
- minimum WordPress version;
- minimum PHP version.

Расширение скачивается как zip. Пакет не должен содержать `node_modules`, полный upstream dump, temp files, OS junk или скрытые служебные директории. В будущей реализации zip пакета должен проходить checksum/signature validation.

В версии `0.1.65` marketplace UI, installer runtime, updater runtime и billing runtime не реализуются.

## Ownership And Data Boundaries

SONYRA и ИП Катаев С.А. являются поставщиком платформы, лицензиаром, продавцом, оператором сопровождения и обновлений.

Клиент, арендатор или хозяин конкретного сайта управляет своим WordPress-сайтом. Формулировки в UI и документах не должны создавать впечатление, что SONYRA распоряжается клиентским сайтом или получает доступ к содержимому сайта без отдельного контракта.

Центральная система сопровождения может получать только технический и лицензионный минимум. Контент сайта, заявки клиентов, персональные данные клиентов, тексты страниц и полный журнал согласий не передаются.
