# SONYRA Owner Console Contract

Этот документ фиксирует будущий отдельный слой центральной системы сопровождения, мониторинга, лицензий, обновлений и биллинга SONYRA Site Platform.

В версии `0.1.65` runtime-код центральной системы, billing UI, monitoring client, installer и update runtime не реализуются.

Начиная с версии `0.1.67`, SONYRA Site Manager содержит только Notice Center foundation для будущего обращения в систему сопровождения. Реальная отправка support event, Owner Console runtime и внешний transport не реализуются.

## Роли

- Клиент, арендатор или хозяин конкретного сайта управляет своим WordPress-сайтом и его содержимым.
- SONYRA / ИП Катаев С.А. является поставщиком платформы, лицензиаром, продавцом, оператором сопровождения и обновлений.
- Центральная система сопровождения отвечает за мониторинг, лицензии, обновления и техническое состояние без доступа к контенту клиента.

## Назначение центральной системы

Будущая центральная система сопровождения нужна поставщику платформы для:

- списка сайтов;
- карточки сайта;
- лицензий;
- оплат;
- грантовых и бесплатных доступов;
- статуса обновлений;
- версий SONYRA Site Manager;
- версий расширений;
- health status;
- heartbeat;
- ошибок;
- доступности сайта;
- SSL;
- REST;
- cron;
- критических событий;
- связи с `updates.dobromap.ru`.

## Что может отправлять клиентский плагин

Клиентский SONYRA Site Manager в будущей реализации может отправлять только технический и лицензионный минимум:

- `site_id`;
- домен;
- WordPress version;
- PHP version;
- SONYRA Site Manager version;
- список SONYRA-расширений;
- версии расширений;
- license id/status;
- heartbeat timestamp;
- health status;
- update errors;
- fatal errors summary;
- REST health;
- cron health;
- mail health;
- SSL health;
- documents/cookie/consent health status без персональных данных.

## Что не передаётся

Центральная система не должна получать:

- контент сайта;
- заявки клиентов сайта;
- персональные данные клиентов сайта;
- тексты страниц;
- полный журнал согласий;
- содержимое форм;
- сообщения;
- заказы;
- платежи;
- raw tokens;
- raw auth sessions;
- cookie пользователей;
- произвольные таблицы.

## Future Support Event From Notice Center

Будущий support event может стартовать из Manager Notice Center, если notice имеет `support_allowed: true`.

Разрешённый будущий payload:

- `site_id`;
- домен;
- WordPress version;
- PHP version;
- SONYRA Site Manager version;
- `error_code`;
- `notice_id`;
- current manager route;
- time;
- health summary;
- optional user comment.

Запрещено передавать контент сайта, заявки клиентов сайта, персональные данные клиентов сайта, тексты страниц, содержимое форм, полный журнал согласий, raw tokens, auth sessions или cookie пользователей.

В `0.1.67` hidden modal foundation может существовать, но support send и fake success запрещены.

## Разрешённые формулировки

В будущих UI и документах можно использовать формулировки:

- Подключить к системе сопровождения;
- Подключить к мониторингу;
- Подключить к контролю лицензии и состояния сайта;
- Код подключения к сопровождению;
- Статус связи с системой сопровождения;
- Проверить связь с системой сопровождения;
- Центральная система сопровождения;
- Центральная система мониторинга;
- Система лицензий и обновлений.

## Запрет на неверную семантику

В UI и документах нельзя использовать формулировки, которые создают впечатление, что SONYRA распоряжается клиентским WordPress-сайтом, подключает сайт к личному кабинету поставщика как к управляющему субъекту или получает доступ к содержимому сайта.

Запрещён смысл:

- клиентский сайт передаётся под управление поставщика;
- центральная система получает контент сайта;
- центральная система получает персональные данные клиентов сайта;
- центральная система получает полный журнал согласий;
- центральная система заменяет локальный SONYRA Site Manager;
- удалённый API исполняет код расширений вместо локального WordPress-плагина.

## Связь с updates.dobromap.ru

`updates.dobromap.ru` является техническим приватным репозиторием, сервером пакетов, лицензий и обновлений.

Центральная система сопровождения может использовать его для проверки версий, лицензий, package metadata, checksum/signature и compatibility. Эта связь не означает удалённое управление контентом сайта.

## STOP-условия будущих этапов

Нужно остановиться, если этап требует:

- передавать контент сайта в центральную систему;
- передавать персональные данные клиентов сайта;
- передавать полный журнал согласий;
- исполнять код расширения удалённо по API;
- обходить WordPress installer/upgrader;
- ослаблять checksum/signature validation;
- добавлять billing runtime без отдельного billing contract.
